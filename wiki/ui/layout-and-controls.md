# Layout and Controls

Made uses one native window with workspace tabs above a content area, a selected left surface (terminal or full-left preview), and a full-height Explorer in the right column. The terminal card owns the only glass layer in the terminal surface (`BG_TERMINAL_GLASS`, 160/255), switching to opaque `BG_TERMINAL` in alternate-screen TUI mode; its body/chrome add no second glass, and the optional session strip stays opaque `BG_HEADER`. The normative layout and interaction contract is [`specs/made-ui-ux.md`](../../specs/made-ui-ux.md). This page maps the implemented composition in [`ui.rs`](../../crates/made-app/src/ui.rs) and [`explorer_view.rs`](../../crates/made-app/src/explorer_view.rs).

## Window geometry

| Region | 1280×800 | 720×480 |
|---|---|---|
| Window gutter (left/right/bottom) | 4 | 4 |
| Floating header | 1272×26 at `(4,6)` | 712×24 at `(4,5)` |
| Band above/below strip | 6 | 5 |
| Main content | 1272×758 at `y=38` | 712×442 at `y=34` |
| Explorer column | 364 total: 4 pane gap + 360 card | 292 total: 4 pane gap + 288 card |
| Left terminal/preview | 908×758 | 420×442 |
| Explorer hidden | Left surface gets full 1272×758 | Full 712×442 |

Panels have no separator lines; cards and gaps do the grouping. The Explorer is always full content height, never reduced by preview. At 1100+ width the Explorer defaults to 360px. At 900–1099 it defaults to 35% of usable content width, clamped to 288–360px; below 900 it uses compact header/radii and a 288px default; the 4px gutter and pane gap are the same in both layouts (`gap` 8/6 remains for other spacing). `min_left_width` is unchanged. Essential controls must fit or move to labeled overflow, never clip.

## Header and workspace tabs

- Floating header: no persistent band fill, border, shadow, or top highlight. The 26/24 strip equals the workspace tab height; the header row spans gutter..width-gutter with no extra horizontal padding, tabs start at the card/window content left edge, and the strip is vertically centered in a 38/34 band (6/5 above and below, `header_top`), so the card content top is 38/34 (`content_top`).
- Left: editor-like workspace tabs start at the content left edge. The cached two-tone monospace `MADE` wordmark (mint `ACCENT` `M`, primary `ADE`, 14px, 1.8px tracking) sits between the tab strip and the right icon group, with a reserved 24px wide / 18px compact strip-side gap and an exact 24/18 icon-side gap; it has no tab fill/hover/selection and no divider. The header wordmark is the About trigger: tooltip and accessible name `About`, pointer cursor, at least 24×24 target, focus ring, and Enter/Space activation; it opens About only while a workspace is active. The update dot sits 3px right of the wordmark's glyph ink, centered on the cap top (`wordmark_ink_rect`, `update_dot_center`); position against visible letters with glyph ink, not the galley box. The Open workspace card wordmark stays brand-only and keeps its “Minimal Agentic Development Environment” tooltip.
- Selected-tab stroke follows the [UI spec](../../specs/changes/archive/20261029-made-ui-ux-v1/spec.md). Selected uses opaque `BG_TAB_SELECTED` with a `TEXT_PRIMARY` 13.0px label; idle uses `BG_TAB_IDLE` with secondary 12.5px text at 0.72 opacity; hover uses `BG_TAB_HOVER` with a primary label, and a selected tab keeps its own fill on hover. Selection styling has no accent outline, underline, dot/hollow marker, or width animation. Tabs use stable workspace-scoped ids and an overflow list when needed.
- Labels, icons and dots: every tab reserves a 16px leading icon slot at the 10px inset (app-drawn terminal glyph, or the program's vendored mark while that program's presentation applies; precedence OpenCode active > Claude Code present > Grok open > shell, locally and over SSH). Labels are dynamic: a shell tab, local or SSH, shows the basename of its shell cwd and follows `cd`; a program tab shows its active session title, else the catalog label. `workspace_tab_base_width` in [`ui.rs`](../../crates/made-app/src/ui.rs) clamps the base width to 96–280 (84–230 compact), and up to 8 session dots add at most 31px. Contract: `Brand and Workspace Tabs` in the [UI spec](../../specs/made-ui-ux.md); per-program presentation: [OpenCode](../integration/opencode.md), [Grok](../integration/grok.md), [Claude Code](../integration/claude-code.md).
- SSH host badge: every SSH-bound tab overlays the host bar's server glyph at the bottom-right of the leading slot, with a cutout ring in the tab fill, and changes shape while the transport is disconnected, reconnecting or failed; the tooltip starts with an `SSH:` line. Local tabs have none. Same `Brand and Workspace Tabs` requirement.
- Close “×”: hidden at rest for every tab, including the selected tab, while its 24×24 target and keyboard focusability stay reserved. It fades in at the fixed 14px size on tab hover or when the tab/close has keyboard focus via the same ~0.15s crossfade (session dots fade out, `×` fades in; reverse on leave), with no scale animation. Hovering the X paints no close background and turns only the glyph `ERROR`; tab width, label truncation, and layout do not change. The parent tab uses `BG_TAB_HOVER` (or keeps `BG_TAB_SELECTED` when selected) and a primary label. The parent tab tooltip is suppressed so “Close workspace” is the tooltip shown.
- Tab-strip tail: the app-drawn `+` (tooltip and accessible name `Open workspace`) sits after the last visible tab and before the overflow trigger, reserved in the tab-fitting budget. It always opens the [Open workspace screen](#open-workspace-screen) directly; there is no menu and no SSH header action.
- Right: icon-only Sessions (when shown) then Explorer, left-to-right so Explorer is rightmost. The last icon’s 26/24 target, selected/hover fill, and focus ring all end exactly at the card right border (`content.right`) with no gutter overhang; the 14px glyph stays centered in its target with normal optical padding. Each has a monochrome app-drawn glyph at 0.80 opacity when inactive, at least 24×24 target, matching tooltip, accessible name, and visible focus; hover is `BG_HOVER` and selection is `BG_SELECTED` without a border or accent bar. No persistent action text labels; no version row. Session-map strip/tabs remain 36/34 and 28/26.
- The Explorer toggle is the only hide/restore action and remains keyboard reachable.

## Explorer

- Full-height right card using `BG_CARD_GLASS` at 188/255 without a native backdrop (off/unsupported/failed), or `BG_CARD_GLASS_NATIVE` at 24/255 when macOS HudWindow or Windows 11 Acrylic is actually applied; same RGB pair, 1px border, radius 10/8, painted glass shadow.
- Card header 34/30 uses `BG_HEADER_GLASS` at 194/255 without a native backdrop, or `BG_HEADER_GLASS_NATIVE` at 32/255 when the native effect is applied; same RGB pair, 1px top highlight. The file tree shows `EXPLORER` and the root name, and the git view shows `REPOS` plus the head line in that slot ([UI spec](../../specs/made-ui-ux.md)). The explorer paints the status snapshot and does not run git; see [`explorer_view.rs`](../../crates/made-app/src/explorer_view.rs).
- Source-control behavior is in the [UI spec](../../specs/made-ui-ux.md). Grouping is [`group_status`](../../crates/made-app/src/worktree.rs). A changed folder or file row paints one right-side dot.
- Hiding/restoring animates the panel width over about 150 ms with quadratic ease-out. The tree stays laid out at its stored width and is clipped to the sliding panel, so content does not reflow. Reversal settles at the stored width; closed state removes tree/splitter input.
- Resize is pointer-drag only on the 4px pane gap, which paints nothing at rest: no full-height line, no boxed grip. Hover fades in a filled, fully rounded 2×32 capsule (`SPLITTER_CAPSULE_SIZE`) centered in the gap at partial-opacity `BORDER_CONTROL` over about 0.14 s; dragging uses the restrained mint `ACCENT` with the same geometry, and leaving fades it out. The hit area is 6px centered on the gap (`SPLITTER_HIT_WIDTH`: gap plus each card's 1px border), and egui's `interact_radius` adds reach; in egui 0.37 every widget under the pointer counts as hovered, so a wider hit rect would show the affordance over card edges. Hover alone does not change width. It keeps a resize cursor and “Drag to resize explorer” tooltip and is not a keyboard Tab stop.
- Width, visibility, expansion, and valid selection survive tab switches and hide/restore, not app restart.
- Tree rows are 24px high with a 4px horizontal inset, 6px radius, a 16px icon slot inset 4px within the painted row fill (slot starts 8px from the row's left edge), and text starting 28px from the row's left edge plus 14px per depth. Directories and files use distinct glyphs; symlinks and errors are explicit.
- Hover is a borderless radius-6 `BG_HOVER` fill; selected/opened rows use only the inset radius-6 `BG_SELECTED` fill plus primary text, with no row or tree-container focus outline, border, or accent side bar.
- File and directory rows show full-color Material Icon Theme icons in the existing 16px slot. Folders use the theme's closed and expanded variants and keep the brighter expanded label; file icons follow the theme mapping. Symlink, other/special, and error rows keep `@`, `?`, and `!`. Row height, inset, radius, text start at 28px plus 14px per depth, fills, label colors, and the icon/label optical center are unchanged. The authoritative change is [`explorer-file-icons`](../../specs/explorer-file-icons.md). Live refresh is watcher-driven; there is no routine Reload action.
- Keyboard focus entering the tree with no prior selection selects the first visible row without opening a preview.
- The tree scrolls with a floating overlay bar hidden at rest; it allocates zero width and never reflows content.
- Hiding gives the reclaimed width to the left surface without stopping the shell or losing preview/tree state. Restore reconciles changes that occurred while hidden.

## Full-left preview

- Opening a file replaces the entire left terminal surface visually; it is never stacked below the Explorer or split beside the terminal. No preview placeholder exists before a file is opened.
- Card header 34/30: filename, full-path tooltip, understated read-only label, `Copy path`, `Refresh`, and `Close`. There is no age counter, no separate Terminal action, and no left-surface `File` control; Close clears the preview and restores the live terminal and its focus, and reopening is by selecting the file again ([UI spec](../../specs/made-ui-ux.md) `Preview header has no age counter or terminal action`).
- Content uses a 44px right-aligned line-number gutter and 13px monospace code at 18px lines with horizontal scrolling. Syntax highlighting comes from syntect with a plain-text fallback; low-contrast spans are blended toward primary at document build time, not per frame.
- Meta line (`preview_meta`) shows size, language and line count; compact drops the language.
- Binary, invalid UTF-8, over-2-MiB, missing, unreadable, and empty states use safe cards/messages; no raw binary is rendered and there is no write path.
- The hidden shell keeps running and consuming bounded output. Hidden preview input never reaches it. A root change clears the preview, invalidates stale reads, and returns to terminal.

## Open workspace screen

One card replaces the former folder picker, the `+` menu and the SSH server window; it is shown for `+`, `--picker`, last-tab close and the folder-less smoke surface. Contract: the `Open Workspace *` requirements in the [UI spec](../../specs/made-ui-ux.md) and SSH-01/SSH-12 in [`ssh-remote-workspaces.md`](../../specs/ssh-remote-workspaces.md); rationale: [ADR 0012](../decisions/0012-open-workspace-screen.md).

- Bands, top to bottom: host bar (Local first, then saved servers, with `+ Add host` and per-host actions; host management lives here), a notice line for SSH failures, the address bar plus folder tree, the git/worktrees panel, and a two-row launch bar (target row with git indicator, path and change pills; then quiet, centered launch buttons, Terminal first).
- Card geometry: grows with the window, inset 48/32 (16/12 compact) via `open_workspace_card_margins` in [`ui.rs`](../../crates/made-app/src/ui.rs); it uses the Explorer's conditional glass pair (see [Design system](design-system.md)). Folder and worktree rows are 24px (`OPEN_WORKSPACE_ROW_HEIGHT`) with a thin stroked chevron from `paint_disclosure` in [`theme.rs`](../../crates/made-app/src/theme.rs).
- Model/view split: [`open_workspace.rs`](../../crates/made-app/src/open_workspace.rs) is the headless state (host, navigation, generation-tagged git snapshot, effective launch path, buttons) and never spawns or reads git; the Local tree reuses the [`workspace_picker.rs`](../../crates/made-app/src/workspace_picker.rs) model. Remote browsing goes through [`remote_workspace.rs`](../../crates/made-app/src/remote_workspace.rs); remote path keys are `open_workspace::remote_key`, never host paths.
- Change pills and the worktree list come from the hardened read-only git reads ([Security](../security.md#hardened-git-reads)).

## Scrollbars

- Explorer tree, Open workspace folder tree and host bar, preview code, diagnostics body/log, and session-map overflow use floating overlay scrollbars: hidden at rest, thumb-only fade-in over about 120–160 ms when the area is hovered, expand to the 8px bar with a faint track only on bar hover/drag, and fade out on leave. They allocate zero width and never shift layout.
- [`ui.rs`](../../crates/made-app/src/ui.rs) holds the shared viewport-bounded scroll helper; a tall list is capped at the space below its anchor and never pushes a focused row off-screen.
- The terminal scrollback bar is custom-painted with the same rest/hover/fade behavior and the same `SCROLL_THUMB`/`SCROLL_THUMB_HOVER` colors. It keeps its full 8px hit area, paints only the thumb on pane hover, and paints the faint track only on bar hover/drag.
- Fade duration and states are asserted from the scroll style/helper state; temporary Xvfb checks cover rest, pane-hover, and bar-hover states, but the captures are not stored.

## About, diagnostics, and optional session map

- About is an opaque, fixed, centered, non-resizable, non-movable floating card opened from the header `MADE` wordmark while a workspace is active. It shows the MADE wordmark, the Made name and version, and the product description, with a `Show diagnostics` button; the button reveals the diagnostics detail, becomes `Hide diagnostics`, and uses the active accent treatment while open; closing/reopening About returns to the default view. While hidden the card stays compact; revealing diagnostics fades and grows it over about 220 ms to use the available application height, with the diagnostic body taking the remaining space.
- The revealed diagnostics detail is the existing opaque card with a status pill, reason, copy actions, sectioned connection/session/worktree/version/metrics/log detail, a bounded log block, and a path/copy footer.
- Technical state belongs here: workspace identity, latest shell cwd, cwd reporting capability/reason, effective root/source, integration status/reason, versions, revisions, heartbeat, metrics, and redacted logs.
- Inactive optional integration is not a degraded workspace. There is no routine status bar, banner, or empty session strip.
- The optional session map is OpenCode-only and labelled so (show/hide and empty-state text name OpenCode); it is hidden while the running target is Grok Build or Claude Code. It is initially hidden, scoped to the selected workspace, and visually distinct from workspace tabs ([UI spec](../../specs/made-ui-ux.md) `Session map is labeled and scoped to OpenCode`).
- The diagnostics headline summarizes every integration row rather than OpenCode alone; the rule is `Headline summarizes every integration row` in the [UI spec](../../specs/made-ui-ux.md). Generic flows (SSH, launch errors, restart/update) name no program: `Program-neutral wording` in the same spec.

## Interaction and accessibility

- Every persistent keyboard-reachable control has a visible focus state; the pointer-only Explorer divider is skipped. Open workspace card controls and other controls keep focus rings. Deliberate exception: Explorer tree rows/container and Open workspace folder/worktree rows paint no outline; their focus/selection is the inset `BG_SELECTED` fill plus primary text.
- The Open workspace screen's Tab order and Cmd/Ctrl+Enter (Terminal launch) are in the `Open Workspace Screen` requirement.
- IME on/off is owned by egui-winit's per-frame `platform_output.ime` check; a focused, drawn terminal sets `output.ime` every frame ([`terminal_view.rs`](../../crates/made-app/src/terminal_view.rs)). Never send `ViewportCommand::IMEAllowed`/`IMEPurpose` directly: eframe 0.37 applies platform output before viewport commands, so it desyncs from egui-winit, and macOS winit composes dead keys only while IME is allowed, which broke accents after workspace-tab switches and in SSH dialog fields.
- Workspace/session tabs support Tab entry, Left/Right movement, and Enter/Space activation. The terminal is one focus stop.
- A workspace tab is selected by its opaque `BG_TAB_SELECTED` fill and the 13.0px label versus 12.5px idle; selection never relies on color alone. The close X is hidden at rest, appears on tab/close hover or keyboard focus, keeps its inside focus ring, and uses the red glyph only as its direct-hover cue, with tab width unchanged.
- Keyboard focus entering the Explorer tree with no prior selection selects the first visible row without opening a preview. The Open workspace folder tree keeps the former picker's keyboard model (`Tree behavior carried from the picker`).
- Targets are at least 24×24, text at least 10px, and status never relies on color alone.
- Motion is limited to spinners, hover-triggered scrollbar fades, the splitter fade (0.14 s), the Explorer width transition, the About diagnostics fade/height reveal (~220 ms), and standard control animation; no essential information exists only in motion. Close visibility is state-driven and never scales; splitter motion stays inside the 4px pane gap.
- `accesskit` is not enabled, so platform screen-reader exposure is not claimed. Tooltips and `Response::widget_info` accessible names are set for icon actions.

## Implementation state

The Calm Editor layout is implemented and verified on Linux with headless/UI-model tests plus temporary Xvfb checks at 1280×800 and 720×480. These checks cover the mint header accent, `+` placement, Explorer-rightmost icon order, workspace-tab states per the [UI spec](../../specs/changes/archive/20261029-made-ui-ux-v1/spec.md), tab close, faded splitter, expanded/selected Explorer folder, inline picker tree expansion/selection/collapse/keyboard states (since replaced by the Open workspace screen), preview, explorer scrollbar, terminal scrollback, primary/alternate terminal surfaces, and conditional Explorer glass. Visual captures are ad hoc validation artifacts and are not stored in the repository. The no-native fallback clear uses alpha 215/255; native clear remains 135/255, and Xvfb without a compositor cannot show blending over a light root. Native Linux/Windows compositor behavior and native pointer/keyboard/screen-reader behavior remain unvalidated. A macOS arm64 HudWindow vibrancy/UI rendering check on 2026-10-28 covered windowed, resized, and fullscreen states; Phase 15's exact glass alpha values and Phase 16's conditional Explorer pairs are headless/token-verified, and the 1280×800 native Explorer tint was visually approved by the user on 2026-10-28. Post-fix native terminal pixel parity and native contrast certification remain pending (the display was locked for the post-fix capture). Windows and macOS x64 remain compile-only. See [Platform matrix](../testing/platform-matrix.md) and [v1 evidence](../records/20261026-v1-evidence.md).
