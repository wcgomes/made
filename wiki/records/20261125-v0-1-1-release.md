# 2026-11-25 v0.1.1 Release

**Status:** `v0.1.1` published 2026-11-25 by `release.yml` run 45641014543 from tag `v0.1.1` at c2f3a6c (bump PR #14). It is the second release from the final `v0.1.0` and the first real upgrade path between published releases. It is not the deleted iteration `v0.1.1` from the [v0.1.0 record](20261106-v0-1-0-release.md). The `add-release-auto-update` change was archived the same day (PR #17); its contract is [`specs/release-distribution.md`](../../specs/release-distribution.md), with UI deltas in [`specs/made-ui-ux.md`](../../specs/made-ui-ux.md).

## What happened

- Attempt 1 lost the macOS arm64 `.pkg` installed-smoke job to runner capacity, so publish and the upgrade check were skipped and nothing was published.
- Attempt 2 re-ran only the failed jobs on the same tag; publish waited for maintainer approval in the `release` environment, then published.
- The post-publish upgrade check (0.1.0 → 0.1.1) had two transient failures (a `macos-15` job never acquired a runner; `gh release download` reported "release not found" for `v0.1.0`). A failed-jobs re-run passed both, so all twelve upgrade jobs passed. Handling is in [Release and CI](../operations/release-ci.md#transient-runner-failures).
- PR #15 made the 10k-row explorer selection timing test report instead of assert on macOS x86_64, where p95 varied about 4x on identical code.

## Evidence

- `CI-release`: installed-layout smoke passed on all seven target/form jobs.
- `CI-upgrade`: 0.1.0 → 0.1.1 in place on Windows setup, macOS arm64/x64 `.pkg` and `.zip`, and Linux AppImage, automatic checks on and off; app data preserved.
- Maintainer report: the in-app auto-update 0.1.0 → 0.1.1 succeeded on their macOS machine, including the About-path restart (architecture and install form not stated).
