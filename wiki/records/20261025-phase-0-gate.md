# 2026-10-25 Phase 0 Bridge Gate

**Decision:** PASS at spike level. 19/19 gate checks and 5/5 supporting checks passed against a real OpenCode v2.1.4 TUI. This proves the integration boundary, not the Made UI.

## Scope and environment

- Linux, OpenCode v2.1.4, Node 24.21.0, tmux 3.6.
- Full session-follow run used `opencode --standalone`; default managed mode was load-tested separately with an isolated service port.
- Isolated `HOME`/`XDG_*`/`TMPDIR`; fixture user config hash unchanged before/after.
- Real linked git worktree used for location change (created with `git worktree add`, not OpenCode's API).
- Token passed through the child environment, never logged; report stores only a fingerprint.

## What passed

- Plugin loaded from injected config and connected; hello, welcome, revisioned state.
- Wrong token rejected with `4401` before state disclosure.
- Loopback URL validation accepted only explicit `ws://127.0.0.1`/`::1` with a port; rejected `localhost`, wildcard, LAN, `wss://`, and missing port.
- Config composition preserved the fixture user plugin, appended Made once, kept `tabs.layout`, forced `tabs.mode=on`/`scope=global`, and passed the five Made options.
- Active tab moved between main and linked worktree; directory changed to the canonical worktree path.
- Bridge focus reached the plugin and changed the active tab; `focus_result {ok:true}`.
- Ping/pong, `request_state`, reconnect (~173 ms, new epoch at revision 1), and graceful goodbye worked.
- Fixture config hash was identical before/after and in the isolated installed copy; fixture user plugin still loaded.
- Token did not appear in bridge events, TUI stderr, or isolated OpenCode logs.

## API divergences that changed implementation

- TUI plugins import `@opencode/plugin/tui`, not `@opencode/plugin`.
- `tabs.list()` has no `unread`; it exposes `promptPulse`, `attention`, `busy`, `renaming`.
- `session.get()` is synchronous/reactive in 2.1.4.
- `tabs.focus()` can open a closed tab; the plugin now checks the list and refuses missing sessions.
- `context.location` follows the active session; `hello.cwd` uses `process.cwd()`.
- A directory package with `tui.ts` loads; a bare `.ts` entry did not.
- Current tabs settings are `tabs.mode`/`tabs.scope`; legacy `enabled` still accepted.
- A transient `activeSessionID: null` (~20 ms) can appear during focus transitions.

## Residual risks carried forward

- Managed-service topology is OpenCode-owned; full follow was standalone-only.
- OpenCode-managed worktree creation/removal was not exercised; gate worktree was git-created.
- Config edge cases (invalid JSON, existing inline overlay, duplicate/disabled entries, migrations) are not fully covered.
- Protocol hardening beyond basic auth/revision was mostly implemented but not fully exercised.
- Plugin path/package shape and app-owned packaging must remain intact.
- Focus was proven bridge-to-plugin, not through a Made UI click.
- Token exposure to same-user processes remains accepted; isolation gaps around OpenCode's own project/skill discovery were observed.
- Linux-only; macOS/Windows and cross-platform OpenCode behavior unvalidated.
- Minor OpenCode API drift remains possible; protocol major gating only catches major drift.
