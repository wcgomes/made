# Tasks: claude-code-integration

Readiness: `analyze` must pass before implementation; review runs `verify` against the persisted spec.

Every implementation handoff carries `Contract ref: specs/changes/claude-code-integration/`. Test-first throughout: write the test, confirm it fails for the expected reason, then implement. Phase gates use the repository's CI commands (`.github/workflows/ci.yml`): `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo clippy -p made-platform --all-targets --locked --features update-test-seam -- -D warnings`, and `cargo test --workspace --locked` (Linux CI runs it serially with `--no-fail-fast`; locally use `-- --test-threads=1` when PTY tests contend). Script tests run as `for t in .github/scripts/test_*.py; do python3 "$t" -v; done`. Tests that need a real `claude` live in an `#[ignore]` suite run with `MADE_CLAUDE_LIVE=1` and claude 2.1.295 or later; a result that cannot be produced is labeled `UNVERIFIED` in the proposal decision index, never claimed as passing.
