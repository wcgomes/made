# Design: ssh-remote-workspaces

## Approach
This is non-normative design overflow: local/remote path authority, SSH lifecycle, plugin transport and remote provisioning interact across existing crates and require meaningful alternatives/security reasoning. Guarantees remain in spec.md. Q1–Q6 are resolved by the user's package approval recorded in proposal.md; engineering choices below implement those outcomes without attributing extra answers to the user. Dependency-ordered executable work and analyze are in tasks.md. No product implementation or live remote proof has run during specification preparation.

The current product is a read-only explorer/preview and read-only source-control observer, not an editor or Git client with mutation actions. “Full parity” includes those actual capabilities and terminal clipboard behavior; it does not justify adding editing/commit features. File updates mean remote filesystem reconciliation, not an invented save/upload UI.

## Significant decisions

### Remote transport alternatives
| Option | Gains | Costs / failure modes | Disposition |
|---|---|---|---|
| Host OpenSSH + SFTP + tmux + small remote scripts | Reuses SSH auth and an external multiplexer | Still needs guarded remote reads, watchers, Git, cwd hooks, private image storage and a loopback plugin relay, and makes tmux a hidden prerequisite. The user correction forbids that dependency. | Rejected. A terminal-only or SFTP-only slice is not parity, and tmux is not a Made requirement. |
| Versioned Made companion over OpenSSH stdio + private tmux | Reuses a known redraw on reattach | Requires tmux 3.2+, probes and fails when it is absent, and treats a user tool as session owner. Superseded by the user correction. | Rejected. Do not keep it as fallback, probe, or manual-install gate. |
| App-owned detached supervisor owning the PTY and a bounded VT resnapshot | No tmux. Same child PID survives frontend loss. Reattach restores modes, mouse, alternate screen, cursor, visible screen, and bounded primary scrollback without replaying commands, input, or the historical PTY byte stream. Reuses TerminalCore observation and the existing TerminalOutput verb, now with a required done bit. | The supervisor must retain primary state across alternate-screen entry; a full alacritty parser dump is not available and must not be invented. Divergence is a stop-and-revise checkpoint, not a reason to call tmux. | Selected. |

A terminal-only SSH subprocess is not an acceptable parity architecture. A local mirror/SSHFS mount is not recommended: it changes path/permission/watch semantics, adds host dependencies and risks treating host cache state as remote truth. An embedded SSH implementation duplicates host auth/config/agent/known-host behavior and is not selected because approved Q2 requires OpenSSH compatibility. User-installed tmux inside or beside the session is irrelevant: Made does not detect it, configure it, attach to it, or use it when the native supervisor cannot meet the resnapshot outcome.

### Model boundary, not a framework rewrite
Introduce the smallest authority-aware operation boundary at the places that currently perform local I/O. A candidate owned identity comprises workspace id, execution authority (local or server connection identity), connection epoch, remote-aware path and root generation. Do not use the client's `Path::is_absolute` rules for a different remote OS. Keep remote path syntax/encoding in the agreed protocol, validating before display or use; never repair a lossy display name into an operation path.

Tree rows, preview classification and UI remain shared where their existing values permit it. Local adapters continue using the existing guarded implementation; remote adapters enforce equivalent constraints where the filesystem exists. Avoid a general distributed framework or new crate hierarchy until the chosen transport and dependency needs justify it. Shared boundary types belong below consumers, not in made-app with reverse imports from explorer/bridge.

Confinement has distinct enforcement points: the client constrains generated operations and validates response authority/tab/epoch/root/path/bounds; the helper on a trusted server enforces actual canonical containment, symlink, file-kind and authorization checks. Neither check replaces the other. A compromised server/helper can forge even well-formed filesystem metadata and content, so client validation is not filesystem attestation. Hostile responses must still be unable to induce host/other-authority reads, local execution, cross-tab state changes or unbounded client work.

### Clipboard modes after Q5 approval
The local default image chord (`Cmd+V` / `Ctrl+V`) still forwards `0x16`; the local fallback (`Cmd+Shift+V` / `Ctrl+Shift+V`) still saves a host-private PNG and pastes its path. For remote panes, both explicit chords use image → PNG → authenticated UploadBegin/Chunk/Commit → server-valid path → existing text paste. This is an explicit remote path-attachment behavior, not remote native clipboard access; the first success explains it. No default-chord `0x16`, clipboard synchronization or automatic upload retry is added. Reuse host image acquisition/encoding caps and remote private-file primitives, add an encoded-size cap, and serialize cleanup in the remote app-owned clipboard directory across tabs. Keep successful PNGs separate from per-tab teardown: seven days/64 files, on start/save, current image protected, no symlink/unrelated-file deletion and no false deletion claims while unreachable.

## Flow
1. Explicit SSH management action collects non-secret record fields; connection testing uses installed OpenSSH and app-owned askpass IPC for host fingerprint, key/password/MFA prompts. Honor aliases/ProxyJump, force agent forwarding/configured network forwards off, never log/persist prompt answers. Unknown host acceptance adds only an app-owned known-host entry; changed keys fail. No host credentials/config are uploaded.
2. User chooses remote Terminal/OpenCode, selects server and remote directory, and confirms exact helper/plugin version/target/files. Detection alone does not authorize staging. Reject, cancel, artifact, or integrity failure leaves local workspaces intact and does not claim terminal-only parity. tmux absent or present does not change this step and is not probed.
3. Create independent tab owner, establish versioned authenticated remote operations, PTY, root and optional integration resources. Keep shell/filesystem startup independent of optional OpenCode integration. Each operation carries authority, epoch, request identity and root generation.
4. Remote shell reports cwd through safe launch-local support. Remote OpenCode plugin reports normalized state through loopback endpoints carried only over SSH or a validated companion relay. Reuse root precedence/session focus semantics without host filesystem validation.
5. Remote filesystem watcher or approved reconciliation strategy reports changes; perform bounded directory/preview/Git work off the UI thread. Apply only replies matching workspace/authority/epoch/generation. Update shared views without synchronous remote calls during drawing.
6. Integration-only loss resets sessionless view and falls back to remote shell cwd. SSH loss drops only the frontend attachment. The detached supervisor keeps the same PTY child, bridge, watchers, and bounded VT state, marks data stale, and drops pending local input/focus/paste. Reconnect uses the in-memory tab capability to authenticate a new transport epoch, exclusively replaces the previous attachment, and applies a generated resnapshot rather than the historical PTY byte stream. A 30-second heartbeat renews a 24-hour detached lease even for inactive tabs. Online close waits asynchronously at most two seconds for owned teardown; unreachable close releases local resources/secrets and reports unconfirmed remote cleanup until the healthy supervisor expires the lease. Never claim reattach after server or supervisor death, and never replay uncertain input.

## Architectural boundaries
- **made-app:** desktop composition root owns server-management/launch UI, selected authority, per-tab lifetime, root arbitration and diagnostics. New `ssh_servers.rs` and `remote_workspace.rs` concentrate registration and remote orchestration; existing `app.rs`, `workbench.rs`, `ui.rs`, `workspace_picker.rs`, `session_follow.rs`, `tui.rs`, `explorer_view.rs`, `terminal_view.rs` and `diagnostics.rs` provide integration seams. Keep file ownership sequenced as tasks.md specifies.
- **made-platform:** remains an OS-capability leaf for host SSH process/PTY facilities, app-owned private storage, credential/agent access if approved, process lifecycle and clipboard/temp-file primitives. No UI, server-registration policy or domain crate dependencies move into it. Remote target OS-specific operations, if a companion is chosen, must respect the same leaf boundary rather than importing host OS assumptions into domain models.
- **made-terminal:** retains emulation and input fidelity; transport/PTY adaptation must preserve resize, exit, cancellation and bounded reads/writes. A transport that merely launches `ssh` without remote cwd/filesystem/integration is insufficient.
- **made-explorer:** owns guarded content reads, listing/preview classification, root generations and tree models. The remote supervisor reuses these against its native POSIX filesystem. Do not make PathGuard canonicalize a host-side remote string. The client remote controller maps bounded directory/preview results into the same visual projection but keeps opaque remote entry/path keys separate from local PathBuf. Local loaders and the server reuse the existing guards/classifiers; no second relaxed path guard is introduced.
- **made-bridge:** keeps authentication, pane/epoch routing and bounded session protocol; no wildcard listeners. If tunneling creates remote sockets, retain bridge ownership/security responsibility and revalidate loopback authority/Host behavior through the actual forwarding path. Do not assume the existing `/made` Host check works unchanged across different forwarded ports.
- **plugin:** remains the only component calling OpenCode APIs; use the consented remote app-owned package unchanged where possible. Never send the host's composed OpenCode config, local provider credentials or filesystem paths to the server; remote user's config is read/composed remotely and remains byte-for-byte unchanged. Manual `opencode` inside a remote shell receives the same launch-local integration environment as direct launch.
- **made-remote (new UI-free library/binary):** owns the remote companion composition and client protocol codec. Library exports authority-tagged wire DTOs/remote client operations; the binary composes platform, explorer, bridge and the shared read-only Git implementation. No crate imports made-app. This explicitly adds a second executable composition root for the remote process, not a reverse dependency or GUI runtime on the server. Preserve made-platform as the OS leaf, made-explorer/bridge as independent siblings and all TCP listener binding inside made-bridge. Move the existing Git implementation into `made-remote::git` and re-export it from made-app::worktree, avoiding an app dependency or duplicated allowlist on the server.

### Concrete inspected interfaces and adaptation
`TerminalPane` currently stores `Option<PtyProcess>` and `PtyOptions` directly (`terminal_view.rs:139–168`); `PtyProcess` exposes bounded write/poll/resize/exit semantics and kills its child on drop. Introduce a narrow TerminalTransport adapter with those semantics in `made-terminal/src/transport.rs`; local PtyProcess remains the default and its drop behavior stays unchanged. Remote detach must not invoke remote Kill: its adapter owns only a host SSH frontend/attachment, while explicit Close is a separate authenticated operation. Reuse TerminalCore/GridRenderer/InputEncoder, not a new remote renderer. On reattach, reset the client terminal and feed only the bounded resnapshot carried as existing `TerminalOutput` bytes. Do not reopen input when `poll` returns empty. Input reopens only after the completing `done: true` frame has been applied. Do not replay historical input or append an unbounded output transcript. Do not add a snapshot verb to `Operation`.

`SessionFollowCoordinator` currently imports std::fs and canonicalizes PathBuf; `made-bridge::state::SessionSnapshot` also validates Path::is_absolute (`state.rs:357–408`). Windows clients cannot use this as POSIX validation for `/project`. Add an explicit path-semantics validation entry to the existing bridge snapshot model (local default unchanged), and a root-resolution port in session_follow. Remote resolution submits a typed server operation and generation; it never calls host fs. Keep the existing snapshot/session/focus model, wrapping accepted remote results in authority/epoch identity instead of inventing incompatible session fields. SessionFocusController routes through a local/remote command sink with the same request id/timeout behavior.

`ExplorerPane` presently starts local directory/preview workers and FsWatcher (`explorer_view.rs`); remote construction selects a remote data controller instead. Existing local TreeModel, PathGuard, PreviewLoader and FsWatcher run server-side; the client stores authority-tagged remote path bytes/entry ids and converts only names/text to sanitized display. Directory expansion remains lazy; selection/expansion can be keyed by remote path, but no remote key is passed to host Path APIs. The server accepts authorized root transitions from explicit selection or validated shell/session/view reports and issues a new root generation. Reconnect resynchronizes generation and all visible/expanded listings; watcher overflow becomes Rescan, not a silent lost update.

### SSH, provisioning and wire transport
Use installed OpenSSH >=8.4 via made-platform process APIs with no controlling terminal (`-T`), `ForwardAgent=no`, `ClearAllForwardings=yes`, `PermitLocalCommand=no`, `StrictHostKeyChecking=ask` and an app-owned `UserKnownHostsFile`. Existing alias/proxy/key configuration is read by OpenSSH; no private key bytes or host inline config are passed to the remote program. App-owned askpass helper plus private OS IPC connects SSH_ASKPASS/SSH_ASKPASS_REQUIRE=force to the native prompt card, including repeated keyboard-interactive/MFA prompts and fingerprint confirmation. Native IPC primitives live only in made-platform; askpass replies are one-use, request-scoped, never sent through terminal/session logs. A changed key remains an OpenSSH hard failure. Tests must prove prompt behavior on all supported host OSes; unavailable capabilities fail explicitly, not via StrictHostKeyChecking=no. App-owned trust additions are allowed, personal files remain unchanged.

A fixed, app-owned POSIX `sh -c` bootstrap is the constant remote command; stdin carries only bounded structured data/artifact bytes, never interpolated script source. It probes OS/architecture/glibc and optional OpenCode metadata and reads home on the remote machine. It does not look for tmux. This avoids a `sh -s` parser buffering protocol bytes before exec. Separate read-only probe/staging/attach SSH attempts may prompt again; no password is cached to avoid those prompts. For staging, consent precedes any remote write. Ship all four headless remote binaries and the complete plugin package with a pinned hash manifest in the desktop distribution; no runtime download, Rust compiler, or npm install is needed on the server, and this change does not authorize installing either toolchain or tmux into a development container. Verify local package hashes, copy only allowlisted filenames into a newly created private version staging directory, verify with remote sha256sum or shasum, atomically promote and never follow a pre-existing symlink. Missing checksum capability is a declared preflight failure with manual instructions, not a verification bypass. Fail unsupported libc/OS/arch or missing package before attempting execution. OpenCode is probed but never installed; provide manual instructions and retry/cancel only for that optional program or for a real target/checksum failure. The supported remote PATH excludes empty/relative entries for executable detection. Capability version probing may execute a bounded OpenCode version command but never launches its TUI and never executes tmux.

Remote roots: Linux `$XDG_DATA_HOME/made` (absolute only, else `$HOME/.local/share/made`), macOS `$HOME/Library/Application Support/Made`; resolve using remote platform facilities only. Layout: `remote/<version>/<target>/made-remote`, `remote/<version>/<target>/plugins/opencode-made`, `remote/runtime/<random-tab>/` for capability, lease, bootstrap metadata, and the private supervisor control socket, and `remote/clipboard-images/` for retained PNGs. Dirs are 0700, secret/state/PNG files 0600; executable 0700. No host XDG/HOME/env value chooses these paths. Existing matching artifacts are verified before reuse; keep artifacts while a live session uses that version; failed staging removes only owned temporary entries. Version/package consent remains app-owned non-secret state separate from server launch metadata.

The new protocol is length-prefixed, major-versioned JSON/binary payload frames over SSH stdin/stdout; stdout contains protocol only and bounded sanitized stderr is diagnostic only. Frame cap 256 KiB, binary chunks at most 64 KiB, at most 16 in-flight nonterminal requests and 256 queued data chunks per tab; preview at most 2 MiB, upload at most 128 MiB encoded, listings stream capped batches rather than one giant frame. Every operation carries tab capability, authority id, transport epoch, request id and root generation; path bytes are losslessly encoded POSIX bytes (NUL/relative/traversal rejected), distinct from display text. Capabilities are generated randomly per tab, held only in client memory/private remote runtime, and never placed in process argv. Bootstrap/auth bytes go through stdin, not shell interpolation. Operations are a closed enum: Capabilities, Open/Attach/Close/Heartbeat, RootValidate/Select, List, Preview/Refresh, Watch/Rescan, fixed GitRead, SessionState/Focus, TerminalInput/Output/Resize, UploadBegin/Chunk/Commit/Abort. No arbitrary exec or file-write RPC beyond scoped staging/upload exists; user terminal input is a separately labeled interactive capability.

Each SSH frontend connects to an authenticated remote per-tab supervisor loopback RPC endpoint implemented in made-bridge, with a five-second bootstrap/auth deadline and no state before capability authentication. made-platform detaches that supervisor from the SSH session: new session, SIGHUP ignored, inherited stdio closed, private runtime directory. The supervisor process, not the frontend, holds the `PtySession`. Frontend death does not close the PTY master or signal the child. A new attach atomically increments epoch, drops only the previous frontend and its pending input, and does not spawn a second child. The supervisor then emits a bounded resnapshot as `TerminalOutput` after `Attached`, and does not emit live PTY bytes until the completing frame. Nonterminal control and terminal traffic have separate bounded priority queues over the same SSH stream; watcher rescan/state coalescing may replace redundant notifications, never arbitrary terminal bytes mid-escape sequence, and never a resnapshot frame with a live frame. On a slow or dead attachment, detach it and generate a fresh bounded resnapshot on the next exclusive attach; do not retain an unlimited output replay log. An empty poll is not that fresh resnapshot's end.

### Durable terminal and cwd reporting
One app-owned supervisor per tab owns the PTY through `Platform::spawn_pty` / `PtySession`. The child is the shell or OpenCode process, started from a fixed companion child-exec wrapper whose program, cwd, and env come from private structured state, not from a shell string and not from tmux. Scrollback retained by the supervisor's `TerminalCore` stays at the existing 10,000-line bound. made-platform owns process detach, PTY lifetime, resize, and scoped process-group termination. Losing the SSH frontend never kills that PTY session. Reattach does not create a second PTY.

The supervisor feeds PTY output into `TerminalCore` while detached. Public observation used for resnapshot is `snapshot`, `history`, `input_modes`, and `alternate_screen`. There is no public accessor for alacritty's private inactive grid, and none is added by reaching into that crate. While the active screen is primary, the supervisor retains the latest primary snapshot, bounded history, and primary input modes. A feed chunk that enters alternate screen is split at that transition so the retained primary state is the pre-transition state, not the alternate grid. On exclusive attach the client resets its terminal and feeds a generated byte stream, not the stored PTY history: primary screen and bounded scrollback, primary modes, then alternate-screen enter plus alternate contents and current modes when alternate screen is active. Sequences must be ones the existing `TerminalCore::feed` parser turns back into the same `InputModes`, mouse reporting, cursor, and `alternate_screen` flag. Leaving alternate screen later is ordinary relayed PTY output; because the client entered alternate screen through the parser, its saved primary grid is the one painted by the resnapshot. This is not a full DEC private-mode dump. Origin mode, wrap, scroll region, charset, and palette are not claimed beyond what the visible cell snapshot and `InputModes` already expose. If a round-trip test cannot restore modes, mouse, alternate screen, and the bounded primary screen without replay, stop and revise this contract. Do not call tmux.

`Capabilities.tmux` stays on the frozen major-1 struct because `deny_unknown_fields` would reject a removed field. Producers encode `false` without executing tmux. Consumers ignore the field, including a stale `true`. No new `Operation` variant carries the resnapshot, and `PROTOCOL_MAJOR` stays 1. The only authorized payload change is the existing verb:

```text
TerminalOutput { data: Chunk, done: bool }
```

replacing `TerminalOutput { data: Chunk }`. `done` is required. Do not give it a serde default: a missing bit is malformed, not `false` and not completion. A `done: false` frame must contain at least one byte. The completing `done: true` frame may be empty, and any bytes it carries are still resnapshot. After `Attached`, the order is zero or more `done: false` resnapshot frames, exactly one `done: true` frame, then live `done: false` frames. A second `done: true` before the next `Attached` is malformed. `Attach` and `Open` still complete only with `Attached`; this bit is not a `ReplyProgress` completion and must not be routed as the unary reply that rejects later terminal frames. `is_terminal` still matches every `TerminalOutput`. `TerminalTransport` stays poll/write/resize/status/detach; `PtyEvent::Data` still has no chunk meaning, so the remote client must not drop `done` when it enqueues bytes. Detach still does not send `Close` or kill the remote child. `PathSemantics` and `SessionSnapshot` are unchanged. A implements the codec. C emits the sequence. B preserves the bit. The desktop input gate consumes it and must not infer the end from an empty poll.

The first vertical-slice checkpoint must prove real OpenCode fidelity and same PID survival on a server with tmux absent before the remaining feature work is integrated. A missing local Rust toolchain or companion binary is unrun, not a pass, and is not permission to install Rust or tmux.

Reuse ShellLaunchPlan for bash/zsh/fish without personal profile edits, with an optional app-owned cwd-report sink independent of the visible terminal stream; do not rely on OSC 7 surviving a detached attachment or on prompt scraping. The hook emits bounded encoded cwd data into a private nonblocking reporting channel established at launch, alongside existing startup/prompt behavior. The helper validates actual remote directory availability and publishes shell cwd even while detached. Unsupported/restricted shells report their fallback capability honestly. Existing shell callbacks must not run remote discovery commands inside an already-running shell. Tests include user hooks and a shell cd during detachment followed by correct fallback after OpenCode exits.

### Remote OpenCode loopback bridge
The persistent remote supervisor starts `made_bridge::server::start(BridgeOptions)` on `127.0.0.1:0` for that remote tab. The plugin URL is that actual remote address (`ws://127.0.0.1:<port>/made`), so the existing Host/Origin checks and one-second plugin-auth deadline are preserved unchanged: there is no synthetic Host rewrite or direct plugin connection to a host port. The remote supervisor consumes BridgeEvent, coalesces snapshots and relays normalized state/focus outcomes through the authenticated SSH frontend; desktop Focus commands travel back over that same channel to the remote BridgeHandle. This is application-level forwarding under SSH, not public TCP or `ssh -R/-L` forwarding. The desktop does not start a second plugin bridge for a remote tab. All remote TCP endpoints remain bound inside made-bridge; no listeners are added to made-app, made-remote or made-platform.

On the server, `ComposeOptions::new(remote_plugin, remote_install_root, actual_loopback_url, token, pane, app_version)` reads only the remote user's config and inline env, preserves plugin composition, forces launch-only tabs, and passes `ComposedConfig::env_pair()` to the remote shell/TUI. ConfigGuard captures/verifies remote bytes before/after, without rewriting. Linux honors remote XDG config; macOS must resolve the existing legacy app-support path and V2-documented XDG/`~/.config/opencode/cli.json` deterministically: use an existing remote XDG/V2 file first, legacy only when the V2 file is absent, otherwise no base. This is a read-only remote resolver; do not migrate or change the local resolver. Documentation consulted: V2 CLI settings explicitly support OPENCODE_CLI_CONFIG_CONTENT and TUI package options. No OpenCode server API or prompt/title scraping is added. Plugin connection stays alive locally on the server during SSH loss, but on desktop reconnect discard old local epoch/view/focus and request fresh state.

## Migration and rollback
No realized spec migration/archive is authorized now. Keep the local adapter and its regression fixtures available throughout implementation. Server registry schema v1 stores only the SSH-01 fields via atomic private app-owned writes; reject unsupported versions and preserve corrupt originals. Editing/removing records affects future launches only; no credentials or live-tab resume capability is persisted. Provisioning uses immutable version directories and per-server/version consent, so rollback selects a matching packaged version for a new session rather than overwriting a live helper/plugin. Partial staging is removed only after ownership checks. Online close requests exact tab teardown, terminates that tab's supervisor-owned PTY session and process group, verifies user config, and removes only owned runtime resources. Unreachable close cannot promise immediate cleanup; the healthy supervisor expires the detached lease after 24 hours. Retained clipboard PNGs follow their separate seven-day/64-file startup/save policy and are not swept by tab teardown. Server/daemon crash and deliberately escaped daemonized jobs are documented limits, never an excuse for broad user-process killing.

## Security considerations
SSH authentication is a transport trust boundary, not permission to execute server-provided commands on the client or bypass root containment. Separate user-operated terminal commands from Made-generated operations: a terminal can run arbitrary user commands, but list/preview/Git/detection/focus must be a constrained surface. Avoid string interpolation of user/server values into shell commands; when a remote launch shell is unavoidable, use a documented narrow bootstrap and tested encoding that handles option prefixes, spaces, Unicode, quotes and metacharacters under the approved remote shell matrix.

Remote and local loopback endpoints still need independent per-tab credentials, pane binding and epoch invalidation; on a trusted server, other users/processes must not obtain state through unauthenticated forwarding. Do not extend v1's same-user inspection residual into an assertion that the remote machine or remote root can be trusted. SSH authenticates the selected peer, not its filesystem claims. A compromised server/helper can lie about paths, guard results and content; Made cannot attest to server honesty or prove remote confinement against that compromise, but must still constrain its generated operations, bound/validate replies and prevent server data escaping into local execution, cross-tab state or unrelated authority reads. Tests must separately exercise real helper containment on a trusted fixture and client resistance to hostile responses, without treating the latter as proof of server filesystem behavior.

First-use trust prompts, app-owned known-host changes, auth prompts, helper/plugin staging, explicit clipboard uploads and same-session survival are user-facing outcomes now resolved by the approved package and normative spec. Consent is still required at runtime; approval to implement is not approval to trust a new host or mutate a particular server without presenting the staging operation.

## Sequencing and validation
The executable single-path tasks, file ownership, interfaces, dependencies, scenario coverage and checkpoints live in tasks.md. Freeze the wire/adapter interfaces first; then SSH platform/askpass, remote service and reusable UI adapters can progress with disjoint files. Do not concurrently modify shared manifests/module declarations or the large Workbench/UI integration files. A first real SSH/native-supervisor/OpenCode survive/reattach slice, with tmux absent, is an execution checkpoint, not an unrun success claim; stop and evolve the contract if detach or the VT resnapshot fails fidelity or persistence. Do not resume the interrupted tmux-based drafts as if they satisfied this outcome.

The controlled acceptance environment uses disposable accounts/keys, isolated known-host/config files, fixture roots and separately invoked mutations, not personal servers or credentials.
