# Proposal: Open workspace redesign

## Intent
Opening a workspace in Made is split across three surfaces: a `+` menu whose rows depend on what is detected (Terminal, then TUIs that always start in the home directory, then per-server SSH rows), a separate folder picker reached only through the Terminal row, and a `Servidores SSH` header window for host management that the user finds confusing. This change replaces them with one Open workspace screen where the user picks a host, navigates to (or pastes) a folder, sees whether it is a git repository and which worktrees it has with their change counts, and launches Terminal or a detected TUI directly in that folder or worktree, with full parity between Local and SSH hosts.

## Non-goals
- Creating, removing, pruning, locking, moving, merging or checking out worktrees, or any other git write, locally or remotely. Made stays observe-only.
- Any change to authentication, host-key trust, credential handling, record schema or storage, companion staging, remote filesystem guards or the compromised-server limitation (SSH-01 paragraphs 2–3, SSH-06, SSH-08).
- New launch programs, launch arguments or launch environments; Grok keeps `dashboard`, Claude Code keeps no arguments, OpenCode keeps its injection (AIA-07 matrix unchanged except the launch cwd).
- Breadcrumbs, favorites, recent folders, folder search, `~` expansion in the address bar, persisting the last host or folder across restarts.
- Changing the startup policy of ADR 0005 (no argument still opens home with no screen).
- Editing the wiki (`wiki/ui/layout-and-controls.md` Picker and `+` sections, `wiki/runtime/terminal-first.md` `+` paragraph and close-last-tab note become stale on archive and must be refreshed by the coordinator then).

## Approach
One screen, three bands. The host bar selects an authority (Local or a saved SSH server) and carries host management, connection state and detected TUIs. The folder band reuses the realized picker tree model unchanged and adds an editable address bar that re-roots on Enter after validating the path on the selected host. The bottom band derives the effective launch path (selected worktree, else selected folder, else root), shows the git indicator, the Worktrees list and change pills from read-only git reads off the UI thread, and offers launch buttons in catalog order for the selected host. Launch semantics are the realized ones (shell tab, direct TUI child, SSH launches under SSH-01/10/11) with the cwd changed from home to the effective launch path. Remote browsing before a tab exists uses a new explicit, screen-scoped listing/validation/git-read grant on the companion helper, bounded and validated on the server as SSH-08 requires for every remote operation. No `design.md`: each decision fits a short entry below and the task plan.

## Decision index
- **One surface:** the Open workspace screen is the former picker surface: shown for `+`, `--picker`, last-tab close and the smoke surface; Close/Escape semantics carried over; Back is removed (user decision, 2026-11-27). A normative terminology rule maps unmodified references to "picker", "Open folder action" and "`+` menu" onto it, avoiding edits to a dozen untouched requirements.
- **`+` never opens a menu:** removes the detection-dependent branch; Terminal is always the first launch button.
- **TUIs launch in the chosen folder, not home:** the user picks the folder first now; the realized "new home-directory tab" wording is modified in the Grok, Claude Code and Degraded Integration requirements.
- **`+` tooltip becomes `Open workspace`:** matches the screen name (see Open decisions).
- **`Servidores SSH` header action removed:** management moves into the host bar; one entry point instead of two (see Open decisions).
- **SSH launch names kept as terminology:** `Terminal SSH`, `OpenCode SSH`, `Grok SSH`, `Claude Code SSH` now name the launch buttons while an SSH host is selected, so SSH-06/08/10/11 stay unmodified.
- **Remote browse grant (SSH-12):** a separate, screen-scoped, read-only grant (directory listing, directory check, existing eight read-only git reads) that ends with the screen or host change; never touches tabs; launch path revalidated on the server.
- **Selecting an SSH host connects:** browsing needs the connection; auth, host-key approval and staging consent use the existing flows; cancel affects only that attempt.
- **Worktrees list only at a working-tree top level with linked worktrees:** main worktree first, then repository order; preselect the item equal to the launch target (the repo root in the common case). A subdirectory shows the indicator but no list, so the user's chosen folder is never silently replaced.
- **Pills reuse `Grouped changes` classification:** order conflicted, staged, modified, untracked; whole-working-tree counts; zero, pending and failed show nothing.
- **Default host:** the active tab's host, else Local.
- **No persistence:** screen state does not survive restart, matching the realized picker.
- **24px rows (user decision, 2026-11-27):** folder tree rows and Worktrees rows are 24px high instead of the picker's 32px, matching the main Explorer tree; 4px inset, radius-6 hover/selected fills and 14px indent per depth are unchanged. Not an open decision.
- **Uniform quiet launch buttons (user decision, 2026-11-27):** Terminal and every TUI button share one style with the designer's tokens: radius 6, height 26 (24 compact), no border or stroke; rest `BG_SELECTED` fill with `TEXT_SECONDARY` label, hover `ACCENT_TINT` fill with `TEXT_PRIMARY` label, pressed `BG_HOVER` fill with `TEXT_PRIMARY` label, keyboard focus the existing 2px gap plus 2px `FOCUS` ring; no accent or primary emphasis on any button beyond that shared hover tint (the realized picker's accent-filled `Use current folder` is retired with it). Terminal stays first and remains the Cmd/Ctrl+Enter target. The hover is a faint mint tint because the Calm Editor palette has no neutral token lighter than `BG_SELECTED`; see open decision 13. Not an open decision itself.
- **Launch bar: left target row, centered buttons (user decision, 2026-11-27, round 2; supersedes the centered-block decision, which superseded the target-row-above-right-aligned-buttons decision):** row 1 is `Launch in`, git indicator, middle-ellipsized monospace path (full path in tooltip) and pills, left-aligned at the footer's content inset; row 2 is the launch buttons, centered in the footer; buttons never move when the path changes; same overflow rule; 720×480 minimums unchanged. Not an open decision.
- **Screen notice line (user decision, 2026-11-27):** every unresolved failure of the selected SSH host (connection, auth, host-key trust, consent, staging, browse open, browse operation, connection test, launch validation) is shown as text in one notice line, `ERROR` color plus an error glyph, dismissible like the test notice, cleared on host change or a later success, never blank while a failure is unresolved; the host badge and tooltip keep reflecting it. Not an open decision.
- **Card grows with the window, conditional glass (user decision, 2026-11-27):** supersedes "opaque card" and the realized `Calm Editor Visual System` text that the picker stays opaque (MODIFIED delta). The card grows in both dimensions with margins 48px horizontal / 32px vertical in the wide layout and 16px / 12px in the compact layout (below 900px), and uses the explorer card's conditional glass pair (`BG_CARD_GLASS_NATIVE` 24/255 with a native backdrop, `BG_CARD_GLASS` 188/255 otherwise) with soft shadow and 1px top highlight; inner fields, rows, pills, notices and buttons keep opaque fills. Margin values and reuse of the explorer alpha pair were chosen by the spec author; see open decision 14.
- **No Back action (user decision, 2026-11-27):** redundant with Close X; Close X and Escape return to the live workspace, otherwise the home/terminal fallback. Not an open decision.
- **Quiet connection-test feedback (user decision, 2026-11-27):** a successful test shows no text notice (no "Connection succeeded. OpenCode was detected..." wording); the host button's connected badge, detected-program marks, tooltip and accessible name are the result. A failed test shows a contextual error notice that is dismissible (keyboard-reachable close control, Escape when focused) and clears on a later successful test or a host change. SSH-01's "each test reports its own result" is kept. Not an open decision.
- **Hardened git reads (user decision, 2026-11-27, after security review of the implementation):** every read-only git invocation forces `core.fsmonitor=false`, `log.showSignature=false`, `protocol.allow=never` and `protocol.<p>.allow=never` for file, git, ssh, http, https, ftp, ftps, ext and fd; sets `GIT_NO_LAZY_FETCH=1` and `GIT_OPTIONAL_LOCKS=0`; and strips inherited `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_CONFIG*`, `GIT_EXTERNAL_DIFF`, `GIT_DIFF_OPTS`, `GIT_EXEC_PATH` and `GIT_ATTR_SOURCE`. Consequence: a user-set `GIT_CONFIG_GLOBAL` is not honored by Made's reads. Selecting a folder must never run repository-defined code or a network fetch. Not an open decision.
- **`--ignore-submodules=dirty` everywhere (user decision, 2026-11-27):** security trade-off: a submodule with uncommitted changes inside no longer shows as modified in tab explorers or pills; only a changed recorded commit does. Realized `Grouped changes` is modified to say so. Not an open decision.
- **Filter drivers by scope (user decision, 2026-11-27):** drivers defined only in global or system scope run normally (git-lfs keeps correct counts); any driver with a key from a repository-controlled scope is neutralized (`clean`/`process` empty, `required=false`), including repo-local LFS (`git lfs install --local`, older `git lfs init`, repo-local `filter.lfs.*`), whose tracked files with dirty stat info may then appear modified; on git older than 2.26 (no `--show-scope`, detected by git rejecting the option) every configured driver is neutralized and status still runs; any other scope-read failure, malformed output or a driver name that cannot be expressed as a `-c` override means status is not run and is reported failed (explorer "Git status unavailable", no pills). The driver-scope read runs only inside the runner's status operation and is not a wire operation (`GitRead` unchanged), so SSH-04 and SSH-08 are not modified. Not an open decision.
- **One git read in flight per browse grant (user decision, 2026-11-27):** bounds remote work during browsing (SSH-12). Not an open decision.

Remote not-detected error: `{catalog label} was not detected on that server. Nothing was started locally.` Remote transport reasons: `The SSH session is not attached.`, `The SSH connection was lost; the remote session state is unknown until it reconnects.`, `The SSH session is connected.` (also for a fresh Terminal SSH tab before OpenCode is seen). Not an open decision.

## Open decisions
Defaults chosen by the spec author; each is a sensible default the requester may overturn before `analyze`/implementation.
1. **`Servidores SSH` header action: removed** rather than kept as a shortcut to the screen. Alternative: keep it as an icon that opens the screen with the host bar focused.
2. **`+` tooltip/accessible name: `Open workspace`** (was `Open folder`). Alternative: keep `Open folder`.
3. **Relation to `--picker` and last-tab close: same surface.** Alternative: a separate, simpler startup picker (rejected: two surfaces to maintain).
4. **Conflicted pill included** as a fourth kind (`N conflicted`, first), since the realized git view separates Merge Changes; the request named staged/modified/untracked as examples.
5. **Worktrees list scope (partly clarified):** shown only when the launch target is a working-tree top level and the repository has at least one linked worktree; preselection is the item equal to the launch target. Alternative: also show it for subdirectories (would retarget launches away from the chosen folder).
6. **Launch bar always visible** with the root as the default target; no separate "confirm folder" step.
7. **Default selected host** is the active tab's host. Alternative: always Local.
8. **Local host address** shows the machine host name (`This computer` fallback). Alternative: no address line for Local.
9. **"Improved design/navigation" scope** is limited to the editable address bar, Up/Refresh toolbar, launch-target display and the new screen layout; the realized tree interaction model is kept. Breadcrumbs, favorites and recent folders are out of scope.
10. **Host bar overflow** scrolls horizontally (no wrap) with the overlay scrollbar.
11. **Detected-TUI marks on host buttons** at 12px, catalog order; pending detection shows no marks.
12. **Remove host** asks for confirmation; open tabs on that server stay open (realized SSH-01 rule).
13. **Launch-button hover token:** `ACCENT_TINT` (a faint mint tint), because no neutral token lighter than `BG_SELECTED` exists. Alternative: add a new neutral hover token (for example `#2B3442`) to the Calm Editor palette, which would be a `Calm Editor Visual System` token addition.
14. **Card margins and glass values:** 48/32px wide and 16/12px compact margins and the explorer card's 24/255 native and 188/255 fallback alpha pair were chosen by the spec author to satisfy the user decision; alternatives are other margins or a separate, more opaque pair for the card if the tree text reads weakly on native vibrancy.
15. **Diagnostics headline details (resolved, coordinator decision 2026-11-27):** "actionable" means an unsupported, degraded or failed row; a row whose program is merely absent (not on PATH, not detected, not installed) is not actionable unless that program is the tab's active program, and such rows still appear in the list; ties go by catalog order (OpenCode, Grok Build, Claude Code); an active program that is present but not yet ready shows its current row sentence.

16. **SSH shell tab tooltip (resolved by user decision 2026-11-27):** the tooltip's first line is `SSH: <server display name> (<[user@]host[:port]>)`, followed by the full remote path; see "SSH host badge on tabs".

## Residual risks (git hardening)
- TOCTOU between reading filter-driver scopes and running status: a repository config change in between can introduce a driver that was not neutralized for that read.
- git older than 2.45 ignores `GIT_NO_LAZY_FETCH`; the `protocol.*.allow=never` overrides still block every transport, so a lazy fetch fails instead of reaching the network.
- Remote-helper protocols (`git-remote-<name>`) not in the blocked list need a helper installed on the host or server to be reachable; `protocol.allow=never` is the default for unlisted protocols, but a server-installed helper is outside Made's control.
- Drivers with any key from repository config are neutralized, including `git lfs install --local`, the older `git lfs init` and any repository-local `filter.lfs.*`; their tracked files with dirty stat information can show as modified (fails safe rather than running repository code).
- On git older than 2.26 all filter drivers are neutralized, so files handled by a trusted global filter (for example git-lfs) can show as spurious modified changes.
- Detecting missing `--show-scope` support relies on git's C-locale error message for the rejected option; a localized or changed message would fall into the fail-closed path instead.
- Long-tail configuration that can run commands or change behavior (beyond fsmonitor, filters, signatures and transports) is not enumerated; new git features may add such keys.
